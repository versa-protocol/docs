# Flags API

Sometimes a receipt Versa retrieved is not the one you expected: a folio that is missing a night, a receipt attached to the wrong booking, a total that does not match the charge. The Flags API lets you raise an issue flag against a transaction from your own systems, exactly as a user would with the "Flag Issue" button in the Versa portal, and read back the status of every flag your team has raised while Versa reviews and resolves it.

The Flags API is served at `https://api.versa.org/flags` and uses the same client credentials as the [Events API](/events_api).

## Quick Example: Flag a booking

<CodeWrap title="cURL Example">
```bash
curl -X POST https://api.versa.org/flags \
  -H 'Authorization: Basic CLIENT_ID:CLIENT_SECRET' \
  -H 'Content-Type: application/json' \
  -d '{
    "identifier_key": "merchant_transaction_id",
    "identifier_value": "my_booking_123456789",
    "notes": "The folio is missing the second night."
  }'
```
</CodeWrap>

Versa reviews the flag, corrects the document where it can, and records the outcome. You can read the outcome back at any time with `GET /flags`, or watch for it in the portal.

## Authentication

Every request carries your client credentials in an `Authorization` header using the Basic scheme, either as the raw pair or base64-encoded:

```
Authorization: Basic CLIENT_ID:CLIENT_SECRET
```

Any client credential of your organization works, whether it was created as a sender or a receiver, in test or production mode. A missing or incorrect credential answers `401` with the body `{"error": "Invalid client credentials"}`.

Every error on this API is a JSON object with a single `error` message.

## API Reference

### Raise a flag

```
POST https://api.versa.org/flags
```

Name the transaction by one of the two ids you already hold for it and say what is wrong. These are the same two ids every [webhook](/webhooks) event carries: the Versa `transaction_id` returned when you posted the event, or the `merchant_transaction_id` you supplied with it.

#### Request Parameters

| Field              | Type     | Description                                                                                                             |
| ------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------- |
| `identifier_key`   | `enum`   | Which id `identifier_value` is: `transaction_id` or `merchant_transaction_id`.                                          |
| `identifier_value` | `string` | That id's value, for example `txn_555raszzb2esgvra33qn9kyw6t` or `my_booking_123456789`.                                |
| `notes`            | `string` | What is wrong, in your words. Trimmed; between 1 and 255 characters.                                                    |

#### Example Request: Flag by Versa `transaction_id`

```bash
curl -X POST https://api.versa.org/flags \
  -H 'Authorization: Basic CLIENT_ID:CLIENT_SECRET' \
  -H 'Content-Type: application/json' \
  -d '{
    "identifier_key": "transaction_id",
    "identifier_value": "txn_555raszzb2esgvra33qn9kyw6t",
    "notes": "The receipt attached is for a different guest."
  }'
```

#### Response

`201 Created` with the flag in the same shape as a list item (below). Its `status` starts as `open`.

| Status | Meaning                                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `400`  | `notes` is empty or too long, or `identifier_value` is blank.                                                                        |
| `404`  | No transaction of your organization carries that id, or it has been deleted.                                                         |
| `409`  | The transaction already has a flag awaiting resolution, or the id matches more than one transaction (a reused `merchant_transaction_id`). |

A transaction carries one open flag at a time. Add to the open one through the portal rather than raising a second.

### List flags

```
GET https://api.versa.org/flags
```

Your organization's flags, newest first. By default only active flags are returned: those still awaiting resolution.

#### Query Parameters

| Parameter                 | Type      | Description                                                                                                        |
| ------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------ |
| `active`                  | `boolean` | `true` (default) returns flags awaiting resolution; `false` returns every flag.                                     |
| `status`                  | `enum`    | Exactly one status: `open`, `in_review`, `corrected`, `failed`, or `no_action`. Overrides `active`.                 |
| `direct_transaction_id`   | `string`  | Only flags on the transaction with this Versa id.                                                                  |
| `transaction_id`          | `string`  | Only flags on the transaction with this Versa network `transaction_id` (as returned when you posted the event).     |
| `merchant_transaction_id` | `string`  | Only flags on the transaction you identified with this id when you posted the event.                               |
| `limit`                   | `integer` | Page size, 1 to 100. Default 10.                                                                                   |
| `page`                    | `integer` | Zero-based page index. Default 0.                                                                                  |

#### Example Request: Flags on one of your bookings

```bash
curl 'https://api.versa.org/flags?merchant_transaction_id=my_booking_123456789&active=false' \
  -H 'Authorization: Basic CLIENT_ID:CLIENT_SECRET'
```

#### Flag fields

| Field                  | Type              | Description                                                                                                   |
| ---------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------- |
| `id`                   | `string`          | The flag's id.                                                                                                |
| `status`               | `enum`            | Where the flag is in review: `open`, `in_review`, `corrected`, `failed`, or `no_action`. See below.            |
| `triage_state`         | `enum`            | What review concluded: `pending`, `working_as_intended`, `incomplete_document`, or `incorrect_document`.      |
| `resolution_state`     | `enum`            | How the flag was closed out: `pending`, `corrected`, `failed`, or `no_action`.                                 |
| `notes`                | `string`          | What was reported.                                                                                            |
| `resolution_notes`     | `nullable string` | Versa's account of what was done, once resolved.                                                              |
| `raised_by_actor_type` | `enum`            | `client` for a flag raised through this API, `user` for one raised in the portal.                             |
| `created`              | `integer`         | When the flag was raised, in Unix seconds.                                                                    |
| `transaction`          | `object`          | The transaction the flag was raised against: its ids, what backs it (`kind`), the merchant, the amount in minor units with its ISO currency, and the booking's property, travel dates and guest where there is one. |

#### Statuses

| Status       | Meaning                                                                              |
| ------------ | ------------------------------------------------------------------------------------ |
| `open`       | Raised, not yet reviewed. Active.                                                    |
| `in_review`  | Reviewed; Versa is working on a fix. Active.                                         |
| `corrected`  | The problem was fixed.                                                               |
| `failed`     | The problem could not be fixed; `resolution_notes` says why.                         |
| `no_action`  | Review found the document and transaction as they should be; nothing to fix.         |
